## Known issues

- Closing a Binance stream takes 2 s on testnet: the server keeps the connection open for 5–9.5 s after the close handshake, and since 2026-10-20 (GitHub issue #20) every engine stream gives up waiting after 2 s instead of the `websockets` default of 10 s (`binanceNotes.md`). A symbol change that replaces or removes a running strategy waits that long while holding that symbol's order lock (from the GUI, 2.6 s and 2.3 s against 7–9 s before), and so do `check` and the shutdown of `run`; a `stop_engine` from the GUI on 2026-10-21 took 2.0 s from the request to "Engine stopped". A GUI start pressed while a stopping engine waits is still refused by the instance lock, and the GUI shows the lock error.
- The instance lock (D-31), the halt record, and the connection file live in each checkout's `engine/state/`. A second checkout, such as a git worktree, therefore isn't refused: its `run` or `trial`, or a GUI run from it (which finds no connection file there and starts its own engine, D-34), would put a second engine on the same account (D-14). Never run them from a worktree until the lock covers the account.
- A backtest whose `--start` comes before the symbol's listing finds no archive files for those months and asks REST for every missing day. Mainnet answered HTTP 429 (2400 weight per minute per IP) for SOLUSDT 15m from 2020-01-01 on 2026-10-19. Start at the first archived month (`binanceNotes.md`), and don't repeat a run that got a 429 right away: repeated 429s get the IP banned (418).
